## 1 About the Hackathon

* **1.1** Teams must develop an AI-based solution for the announced theme or problem during the official hackathon development periods.
* **1.2** The competition includes a three-day initial development phase, a first evaluation of submitted projects, on-site implementation of new requirements, and a second evaluation.
* **1.3** Winners will be selected based on the marks from both evaluations.

---

## 2 Team Participation and Devices

* **2.1** Each team may have a maximum of 3 (three) members. Single-member participation is permitted.
* **2.2** All participating members must be officially registered. Member substitutions involving anyone who was not officially registered in advance are strictly prohibited.
* **2.3** All participants must bring their own devices for the AI Hackathon.

## 4 Development Rules and AI Resources

* **4.1** Teams must generate their ideas and develop their challenge-specific solutions within the initial 72-hour development period. On the final day, teams must implement the new updates assigned after pre-evaluation within the specified on-site time.
* **4.2** AI models, APIs, pretrained models, frameworks, open-source libraries and public datasets may be used unless the challenge brief restricts them.
* **4.3** Pre-existing general-purpose components may be used. However, a substantially completed solution specifically prepared for the announced challenge is not allowed.
* **4.4** Teams must disclose significant external datasets, APIs, services and pre-existing components if requested by the organizers or judges.
* **4.5** Each team must understand its submitted solution and be able to explain its design, implementation and AI components during judging.

---

## 5 GitHub and Development History

* **5.1** Each team must maintain its project in a public GitHub repository. Project files and code must be properly committed and pushed within the applicable contest period so that judges can verify the work.
* **5.2** Teams must maintain a clear and continuous Git commit history throughout both the initial development phase and the on-site update phase.
* **5.3** Bug fixes, feature implementations, improvements and other significant changes must be committed step by step as work progresses. A single final upload does not satisfy the requirement for a continuous development history.
* **5.4** The repository must contain the project source code, required prototype or project files and a complete README.md as specified in Section 6.
* **5.5** Initial project code must be pushed by the initial submission deadline. Final-day updates must be pushed within the allotted on-site implementation period.

---

## 6 Mandatory README.md

* **6.1** Each public GitHub repository must include a complete README.md. Judges must be able to understand, set up, run and test the project by following it.
* **6.2** The README must include all of the following information:

| Item | Required information |
| :--- | :--- |
| **Project overview** | The problem addressed, proposed solution and purpose of the project. |
| **Features** | Implemented features and how the AI components are used. |
| **Technology stack** | Languages, frameworks, AI models, APIs, libraries and services used. |
| **Requirements** | Software, dependencies, hardware or other prerequisites needed to run the project. |
| **Installation and setup** | Complete, step-by-step instructions for installing dependencies and configuring the project. |
| **Environment variables** | Required variable names, their purpose and configuration instructions. Use placeholders rather than publishing secret values. |
| **Run and build commands** | Exact commands to run the project and build instructions, if applicable. |
| **Live deployment URL** | The live deployment link for judges to access the project. |
| **Testing instructions** | How to run tests or verify the implemented features. |
| **Other configuration** | Any additional files, settings, access requirements or configuration necessary to run the project. |

## 7 Submission Requirements

* **7.1** By the end of the three-day development period, each team must submit a video demonstration and a project report file, together with its public GitHub repository link and required project materials.
* **7.2** The video must demonstrate how the implemented idea works, explain the features and AI components implemented, and describe its real-life impact or practical value.
* **7.3** The project report must explain the problem, proposed idea, implemented solution, key features, AI approach and intended real-life impact.
* **7.4** The final submission must include the required prototype or project files and any presentation or demonstration specified by the organizers. The organizers will provide the submission channel and any file-format requirements.

---

## 8 Two-Stage Evaluation

* **8.1 First evaluation – project pre-evaluation.** Judges will review the initially submitted project, video demonstration, report and supporting project materials. This evaluation contributes to the final result.
* **8.2 New requirements on the final day.** At the start of the on-site contest, teams will receive new updates or requirements arising from the pre-evaluation of their project.
* **8.3 On-site implementation.** Teams must integrate these updates into their existing project within the time specified by the organizers. Changes must be documented through the ongoing Git commit history and pushed within the allotted time.
* **8.4 Second evaluation – final demonstration.** The last 1.5 hours (90 minutes) of the on-site contest will be reserved for the second evaluation. Teams must demonstrate the updated project, explain the newly implemented requirements and answer judges' questions.
* **8.5 Final ranking.** Winners will be selected based on the marks from both the first and second evaluations. The detailed marking criteria, score allocation and weighting of the two evaluations will be announced by the organizers.

---

## 9 Originality and Competition Integrity

* **9.1** Work copied from another team or falsely presented as the team's own will result in disqualification.
* **9.2** Permitted external resources and general-purpose components must not be misrepresented as original team work. Teams must provide disclosures when requested, as described in Section 4.4.
* **9.3** Teams must not submit a substantially completed, challenge-specific solution prepared before the official development period.
* **9.4** Every team must be able to demonstrate its project and answer questions about its design, implementation and AI components. All participating members must comply with the registration and substitution rules in Section 2.

---

> ### Timing reminder
