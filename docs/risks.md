# Risk Assessment & Mitigation Architecture

This document formalizes the risk controls enforced throughout the Sathi system architecture.

---

## 1. Financial Manipulation & Automation Risks
- **Risk:** AI agent moving user funds, approving fraudulent credit, or automating unwanted fees.
- **Control (Invariant 8):** Sathi **never moves money** and has no permission or API bindings to execute financial debits or credits. Saving a goal creates a metadata record only.
- **Control (Invariant 1):** The LLM never computes financial arithmetic. All math is performed by pure deterministic functions in `core/money.py` and `core/planner.py`.

---

## 2. Hallucination & Misleading Financial Advice
- **Risk:** LLM hallucinating unrealistic savings projections or phantom balances.
- **Control (Invariant 2):** `llm/validator.py` enforces a **fail-closed numeric validator**. Every digit and currency figure generated by an LLM is extracted and matched against tool outputs. Any unmatched number triggers an immediate fallback to a pre-reviewed template.
- **Control (Invariant 6):** Forecasts are displayed as probability ranges (p10 to p90), never as misleading single-point guarantees.

---

## 3. Prompt Injection & Jailbreaks
- **Risk:** Malicious users injecting prompts to reveal system instructions, alter advice, or trigger inappropriate outputs.
- **Control (Invariant 12):** `llm/sanitizer.py` cleans input text, normalizes unicode, and rejects adversarial injection patterns ("ignore previous instructions", "DAN mode", "transfer money").

---

## 4. Privacy & Data Leakage
- **Risk:** Unauthorized access to user financial data or cross-user data leakage.
- **Control (Invariant 7):** All personal data routes are strictly scoped under `/v1/me/*`. No endpoint accepts a `user_id` query or body parameter; `user_id` is extracted exclusively from the verified HMAC-SHA256 JWT token in `api/auth.py`.
- **Synthetic Data Baseline:** No real customer PII was ingested or processed during the competition.
