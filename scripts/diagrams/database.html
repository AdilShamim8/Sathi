DESIGN NOTES
Salary fields are user intent, not detection. Recurring salary is still learned from transaction history (MAD-regular monthly streams); the explicit fields only refine the user's declared plan — the optional input requested for the demo.

role/mode separate the device owner from personas. Exactly one User has role “owner” — the real app user (mode “personal” or “demo”). Synthetic reference personas (role “persona”) power the /api/v1 surface and never mix into the owner's numbers; a full reset deletes only owner data.

ForecastRecord persists every served prediction (probability, pressure, factors, model version) so later real-world outcomes can be scored — the hackathon's future-validation requirement.

AuditEvent logs LLM interactions and significant engine decisions — the human-oversight trail.
